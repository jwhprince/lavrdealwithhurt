# VOLTA — школа танцев

Next.js App Router, React, TypeScript. Одна основная страница, две служебные страницы и серверный обработчик заявок. Шрифты и медиа размещаются локально. По умолчанию это безопасный предпросмотр: индексация и приём заявок выключены, неизвестные контакты не выдуманы.

## Локальный запуск

Нужен Node.js 22+ (проверено на 24.13) и npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Открыть http://localhost:3000. Без настроенной почты кнопка записи откроет сообщение о скором запуске онлайн-записи. При заполненном телефоне или почте предложит связаться со школой. Никаких тестовых заявок с вымышленным успехом нет.

```bash
npm run typecheck
npm test
npm run build
npm start
```

Браузерная проверка: `npm run test:e2e`. По умолчанию используется `/usr/bin/chromium`; для другого установленного Chromium задайте `CHROMIUM_PATH`. Playwright поднимает отдельный dev-сервер на 3100 с тестовыми реквизитами только для проверки формы. Все успешные/неуспешные отправки в браузерных тестах перехватываются; реальная почта не вызывается. Снимки пяти размеров сохраняются в `test-results/`, каталог исключён из Git. Для проверки работающей production-сборки запустить `npm run test:smoke` в другом терминале: проверяются загрузка, ошибки браузера и воспроизведение видео, сохраняются снимки desktop/mobile и локальные показатели загрузки (не полевые Core Web Vitals).

## Контент

- `src/lib/site.ts`: контакты из окружения, описания трёх направлений, необязательные реальные возраст/цена/расписание в `programDetails`.
- `src/app/page.tsx`: восемь блоков, достижения руководителя и тексты.
- `src/app/globals.css`: розово-бордовая палитра, мобильные стили и сокращение движения.
- `materoial/`: неизменённые оригиналы. Оптимизированные ресурсы — `public/images/`, видео — `public/video/`.
- `node scripts/prepare-assets.mjs`: повторно создаёт WebP и OG-изображение. Видео скопировано без перекодирования с MP4 faststart; обложка взята из самого видео.

До публикации владелец подтверждает тексты, достижения, возможность использования фото/видео и итоговое кадрирование. Фраза «5 минут от метро» не опубликована, так как маршрут не подтверждён.

## Настройки и запуск записи

Скопировать `.env.example` в `.env.production` на сервере. Не коммитить секреты. Настройки публичного содержания, документов, домена, индексации и аналитики применяются **при сборке**: после изменения пересобрать и перезапустить. SMTP читается обработчиком на сервере; после его изменения тоже перезапустить процесс. Не переносить собранный с production-настройками сайт на тестовый домен.

1. Заполнить `SITE_URL` реальным HTTPS origin без пути, `CONTACT_PHONE`, `CONTACT_EMAIL` и необязательные социальные ссылки.
2. Заполнить `LEGAL_OPERATOR`, `LEGAL_INN`, `LEGAL_ADDRESS`, `PRIVACY_EMAIL`, `LEGAL_RETENTION`. Согласовать фактическую редакцию `src/components/legal-document.tsx`, состав подрядчиков, сроки и процедуры хранения/удаления с владельцем. Шаблон не является заключением о соблюдении законодательства. Только после этого установить `LEGAL_APPROVED=true`.
3. Настроить SMTP российской рабочей почты: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`, `LEADS_EMAIL`. `MAIL_FROM` и `LEADS_EMAIL` — одиночные адреса без отображаемого имени. Для 465 обычно `SMTP_SECURE=true`, для STARTTLS — `false`; TLS не отключается.
4. Включить `LEADS_ENABLED=true`. Перед публикацией отправить контролируемую заявку, проверить фактическое получение письма, SPF/DKIM и папку спама. Успех API означает принятие письма SMTP-сервисом, а не доказанную доставку во входящие.
5. Настроить доверенный reverse proxy, затем `TRUST_PROXY=true`. Проверить `npm run check:launch`.
6. Установить `INDEXABLE=true` только на рабочем домене, собрать и перезапустить. Сборка отклоняет неполную включённую конфигурацию.

Если данные владельца отсутствуют, документы показывают статус подготовки, форма не собирает данные, а прямой POST возвращает 503. `LEGAL_APPROVED` — подтверждение оператора, а не автоматическая юридическая проверка. Основа для проверки документов: [152-ФЗ, официальный текст](https://mintrud.gov.ru/docs/laws/130).

## API заявки

`POST /api/leads`, `Content-Type: application/json`, `Origin` должен совпасть с `SITE_URL`.

```json
{"name":"Анна","phone":"+79991234567","direction":"baby","consent":true,"website":""}
```

`direction`: `sport`, `baby`, `latina` или пустое значение. `website` — скрытая ловушка спама. Ответ: `{ "ok": boolean, "message": string }`. Сервер проверяет данные независимо от браузера. Коды: 200 — SMTP принял письмо, 400 — данные/спам, 403 — Origin, 413 — размер, 415 — формат, 429 — частота, 503 — выключенная запись/неполная конфигурация/ошибка SMTP. При 429 возвращается `Retry-After`.

Имя/телефон не попадают в заголовки письма, логи или аналитику. Лимит — 5 попыток за 15 минут на адрес, до 10 000 активных ключей в памяти. После перезапуска счётчики очищаются. Приложение рассчитано на **один Node-процесс**. Для нескольких процессов/серверов перед масштабированием заменить limiter общим хранилищем или вынести на ingress.

Без `TRUST_PROXY=true` лимит общий: клиентские `X-Forwarded-For` не считаются доверенными. При включении прокси **обязан перезаписывать**, а не дополнять `X-Forwarded-For`. Node-порт должен слушать localhost и быть недоступен извне.

## Размещение на сервере в РФ

Предполагается один Node.js-процесс за Nginx, HTTPS, сервер и рабочая почта в РФ. База заявок не создаётся; письма хранятся в почте согласно утверждённой политике. Секреты доступны только владельцу сервисного процесса.

```bash
npm ci
npm run check:launch
npm run build
npm start -- --hostname 127.0.0.1 --port 3000
```

Запуск оформляется системной службой с автоматическим перезапуском. Для установки на реальный сервер сначала нужны домен, доступ и выбранный провайдер. Не запускать Node от root. Официальные рекомендации: [Next.js self-hosting](https://nextjs.org/docs/app/guides/self-hosting).

Пример фрагмента HTTPS virtual host Nginx (домен и сертификат добавляются при установке):

```nginx
client_max_body_size 8k;
client_body_timeout 15s;
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_buffering off;
    proxy_read_timeout 60s;
}
```

Настроить постоянный редирект HTTP→HTTPS и единственный выбранный хост, запретить прямой доступ к 3000. Если перед Nginx есть CDN/балансировщик, сначала отдельно настроить доверие к его адресам: нельзя принимать произвольный IP из входящих заголовков. Не логировать тела заявок. Сроки доступа к access/error-логам и почте определяет владелец. Приложение запускается через `npm start` из checkout с установленными зависимостями и собранным `.next/`.

## SEO и аналитика

- Основной текст, H1/H2, адрес и LocalBusiness присутствуют в исходном HTML. Нет выдуманных рейтингов, филиалов и телефонов.
- Без `SITE_URL` canonical и абсолютные OG-ссылки не публикуются. При выключенной индексации — robots noindex, HTTP X-Robots-Tag, запрет обхода и пустая sitemap.
- На рабочем домене sitemap содержит главную; документы остаются noindex со своими canonical. Параметры ссылки не меняют canonical.
- Тестовый домен лучше дополнительно защитить HTTP-аутентификацией. Если уже попал в поиск, Disallow мешает роботу увидеть noindex: для удаления нужна отдельная процедура, а не просто закрытие robots.txt.
- Подтвердить домен в Яндекс Вебмастере (`YANDEX_VERIFICATION`), отправить sitemap, проверить обход/рендеринг и региональность, связать сайт с действительной карточкой Яндекс Бизнеса. [Региональность Яндекса](https://yandex.ru/support/webmaster/ru/site-geography/site-region.html).
- `METRIKA_ENABLED=true` и `METRIKA_ID` включают отложенную загрузку Метрики после согласования документов. Цели: `lead_success`, `phone_click`, `route_click`. Вебвизор и автоматическое отслеживание ссылок выключены, поля формы не отправляются. Проверить требования к аналитике/согласию для выбранной конфигурации перед включением.
- Яндекс Карта загружается по нажатию, маршрут доступен отдельной ссылкой даже при ошибке виджета.

После запуска: проверить фактическую индексацию и поисковые запросы в Вебмастере, доставку заявок и цели Метрики. Расширение SEO на всю Москву и МО требует дальнейшей работы с реальными направлениями и содержанием; один лендинг не гарантирует позиции по всем запросам.
